# Phase 60 — UI Design Contract

> Visual and interaction contract for 保存后面板保持 (Post-Save Panel Persistence). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope discipline (per 60-CONTEXT D-01..D-08):** this phase introduces **ZERO new visual vocabulary**. The user-facing surface is the EXISTING NodeDetailPanel (locked geometry, tokens, tabs) plus two EXISTING info toasts whose *trigger conditions* change. What this contract LOCKS is (a) the panel's stay-mounted behavior across save/reload — no unmount, no width/tab reset, no flash, (b) the toast trigger matrix that makes self-save silent (D-05) and other-client reload audible, (c) the honest-collapse interaction for anchor loss (D-03), and (d) the D-08 negative invariant (stale badge no revival). The client code change is wiring-level (self-echo skip + re-anchor alignment); the executor may not invent any new component, dialog, badge, or string beyond the console.warn named in §Component Contract 2.

## Phase-Specific Component Contract

### 1. NodeDetailPanel stay-mounted contract (PANEL-01 / PANEL-02 — THE acceptance surface)

Existing component (`packages/infinite-canvas/src/components/panel/NodeDetailPanel.tsx`), LOCKED, zero styling change. The contract is behavioral:

- **Self-save path (PANEL-01):** client save-v2 returns 200 → self-echo does NOT trigger loadCanvas (D-01) → `detailNode` never transitions → panel never unmounts → **zero visual delta except the save button state**. The local store already IS the truth; no reload occurs at all.
- **Other-client reload path (PANEL-02):** graph:saved (other origin) → loadCanvas → setGraph swaps the derived model → `detailNode` re-anchored by id (canvasStore.ts L442-447 semantics) → the `node` prop changes object identity but keeps the same id → component does NOT unmount. Consequences, locked as acceptance targets:
  - `panelWidth` (user-resized width) PRESERVED — must not reset to 480 default.
  - `tab` state PRESERVED (`'detail' | 'feedback' | 'iteration'`) — the existing reset effect fires on `node?.id` change only, so same-id re-anchor must not reset the tab.
  - Content renders from reload truth (D-06): stale trio, review status, prompt fields etc. reflect the reloaded graph — the panel is live, not a frozen pre-save snapshot.
- **No intermediate null / no flash:** the re-anchor must be a single atomic store update. Any implementation that clears `detailNode` and restores it across async boundaries is FORBIDDEN — it would unmount/remount the panel (width+tab reset) and visibly flash. The panel render sites (FlowCanvas.tsx:1048 timeline view / :1265 canvas view) are NOT gated on `loading` — keep it that way; do not add a loading gate that would unmount the panel during reload.
- **selectedNode symmetry (D-07):** node selection (selection ring, `selectedNode`) survives reload by the same id re-anchor. Symmetric assertion required: both `detailNode` and `selectedNode` either survive together or collapse together under identical id-miss conditions.

### 2. Anchor-loss honest collapse (D-03 — LOCKED interaction)

- Re-anchor cannot find the same id in the reloaded graph (id drift / node deleted) → `detailNode = null` → panel unmounts (`return null`) + one `console.warn`.
- NO user-facing toast, dialog, or placeholder. NO assetKey fuzzy re-match. NO "panel kept open on stale data" mode. Honest absence is the contract.
- Console.warn is the D-03 acceptance hook (e2e/verify may capture console messages; see §8).

### 3. Toast trigger matrix (D-05 — the one trigger-condition change)

| Event | 「Pipeline 同步了新数据,正在刷新画布…」 | 「检测到 pipeline 远端更新,正在刷新画布…」 | reload? | panel |
|-------|------------------------------------------|---------------------------------------------|---------|-------|
| Self save-v2 → 200, self-echo graph:saved | NO | NO | NO | stays, zero delta |
| Other-client graph:saved (scope-matched) | YES (info) | — | YES | re-anchored, stays if id survives |
| Health-poll detects missed remote write | — | YES (info) | YES | re-anchored, stays if id survives |
| graph:saved other-scope (different pid/eid) | NO (existing scope guard) | NO | NO | untouched |

### 4. Health-poll baseline — interaction MUST (wiring constraint with visible consequence)

The self-echo skip branch MUST retain the existing baseline reset (`lastEventCountRef.current = null`, FlowCanvas.tsx:335-338 today inside onGraphSaved). Mock health `eventCount` = count of save-v2 calls (server.mjs:202-214), so a self-save bumps it; if the skip branch drops the reset, the ≤30s poll fires 「检测到 pipeline 远端更新…」+ reload on the user's OWN save — violating D-05 silence and triggering a pointless reload. Reset stays; skip only the toast+loadCanvas pair.

### 5. SC4 race-case closure (D-08 — negative visual invariant on existing vocabulary)

After a stale rerun completes (`node:state success`), the existing stale badge count (`svg[aria-label="stale"]`) reaches 0 and STAYS 0 — no transient revival. Root cause of the 59 Known Issue #1 revival (self-echo reload racing the success-clear) disappears with D-01. The stale trio vocabulary (triangle + pulse + StaleSection, 59-UI-SPEC §1-4) is untouched; this phase only asserts its absence-after-clear. The `cv-stale-pulse` animation remains expected-but-unasserted (59-UI-SPEC §2 flake-bait rule carries over).

### 6. Mock/real alignment (D-04 — zero-divergence contract)

- Mock save-v2 broadcast shape/timing (5ms delayed echo) stays EXACTLY as-is (server.mjs:185-192). The self-echo skip is implemented CLIENT-side; NO mock knob may bypass the echo for Phase 60 tests (that was 59-04 `suppressGraphSaved`, now obsolete for this purpose — its removal or retention is planner's call, but Phase 60 e2e must pass with the echo LIVE).
- Consequence: the PANEL-01 mock assertion (panel stays open after save) is by construction the real-machine behavior. No mock-only accommodation of any kind.

### 7. Selector / testid contract (e2e + checker hooks — no new testids)

| Selector | Element | Notes |

## Flags for Planner (autonomous-run disclosures)

- **FLAG-1 (wiring with visible consequence):** the self-echo skip MUST retain the health-poll baseline reset (evidence: FlowCanvas.tsx:335-338 — `lastEventCountRef.current = null` lives inside onGraphSaved today; mock server.mjs:202-214 — `eventCount` = save-v2 call count, so self-save bumps it). Dropping the reset while skipping the reload produces a spurious 「检测到 pipeline 远端更新…」 toast ≤30s after every self-save — a D-05 violation the e2e would only catch with a >30s wait; lock it statically instead (§4).
- **FLAG-2 (pre-existing quirk, do NOT fix):** real-backend `/api/canvas/v2/health` returns `nodeCount`/`linkCount`/`lastEventId` per scope — NO `eventCount` field (src/routes/canvas/v2/health.ts:35-42) — while FlowCanvas.tsx:817 reads `scope.eventCount`. The health-poll fallback (and its toast) is therefore structurally inert on the real backend today. This is OUT of Phase 60 scope (D-04 alignment concerns the save-v2 echo path, not health). Executor must not "repair" the field mapping — that would activate a second reload channel mid-phase.
- **FLAG-3 (diagnosis needed — D-02's premise may already be satisfied):** code reading shows `setGraph` already re-anchors both `selectedNode` and `detailNode` by id (canvasStore.ts L442-447), and BOTH `loadGraphFromV2` (L460-471) and `loadInitialGraph` (L477-494) route through `setGraph`. So the store-side alignment D-02 asks for is likely a NO-OP as written; today's real-backend panel collapse must then come from **id drift across the save→reload round-trip** (relational reassembly or V2→V3 adapter id derivation) — exactly D-03's named case. Planner should diagnose where ids diverge on the real backend before writing store-side "alignment" code; PANEL-02's fix may be entirely wire/server-side id stability. Mock preserves ids verbatim (state.canvas passthrough), which is why mock already behaves — consistent with D-04's framing.
- **FLAG-4 (housekeeping):** 59-04's mock `suppressGraphSaved` knob (server.mjs:135/179) is obsolete for its original purpose once D-01 lands (self-echo skip is client-side and always-on). Removing it must keep `phase59-stale-cascade.mjs` SC4 green without the knob (D-12 regression face) — if the 59 e2e hard-depends on the knob, keep it but add a comment; planner decides.
