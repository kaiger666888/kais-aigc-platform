# Phase 59 — UI Design Contract

> Visual and interaction contract for 窄触发 stale 级联 (Narrow-Trigger Stale Cascade). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope discipline (per 59-CONTEXT D-01/D-04/D-05):** this phase introduces **ZERO new visual vocabulary**. The user-facing surface is the EXISTING stale trio — NodeBadges stale 三角 + cv-stale-pulse 脉动、NodeDetailPanel StaleSection、useStaleRerun 双出口 — now driven by a server-side cascade over the two narrow paths (panel-edit-regen / reroll-seed). This contract LOCKS those existing visuals verbatim as the acceptance target (STALE-01/02 "角标可见" / SC4 "一键重跑"), locks the absent-negative (STALE-03: no badge on orchestrate/batch), and specifies the one interaction seam the server cascade plugs into (see FLAG-1). Execute-chain breakpoint fixes (D-06①②④) are data-path only; D-06③ has one user-visible consequence locked in §Component Contract 6.

## Phase-Specific Component Contract

### 1. Stale triangle badge (NodeBadges.tsx — LOCKED, zero change)

- Rendered iff `asset.stale != null` AND `lod !== 0` (LOD0 panorama hides all badges — cascade during panorama view is data-only until zoom-in).
- Geometry: SVG 14×14, `viewBox 0 0 14 14`, absolute at `left: -6, bottom: -6` (V3_NODE_SIZES.badge.tri/offset), polygon `0,14 14,14 0,0`, fill `v3theme.signal.stale`.
- Accessible contract: `aria-label="stale"` + `<title>重跑下游</title>` — the e2e selector `svg[aria-label="stale"]` is THE canonical stale assertion hook (phase52-stale-panel.mjs:68 precedent); MUST NOT change.
- Click: `stopPropagation()` (地雷 #8 — must not bubble to RF onNodeClick / switch detail panel) then `rerunStaleChain(nodeId)`. `cursor: pointer`.
- Coexistence: verdict band (56-03) sits at `left: off + tri + 2` when present — stale triangle keeps its corner; layout already stable whether or not stale is set (no jump when cascade arrives).

### 2. Cascade pulse (useStale.ts — LOCKED, zero change)

- `triggerStaleCascade(changedAssetIds)` → store `markStaleDownstream` + `useStalePulse.addPulse([changedAssetIds, ...newlyStale])`.
- Animation: `cv-stale-pulse 600ms ease-out 1` on the triangle (drop-shadow 4px rgba(240,165,46,0.9) + scale 1.25 at 50%). Pulse set: max 8 concurrent, 1200ms window.
- **Pulse is decorative enhancement, NOT an acceptance target** — e2e asserts badge visibility only (pulse is transient; asserting it is flake-bait). SC1/SC2 assert the badge; pulse is expected-but-unasserted.

### 3. StaleSection (NodeDetailPanel.tsx L1137-1161 — LOCKED, zero change)

- Renders iff selected node has `stale != null`; SectionLabel 「过期状态」+ tinted box + rerun button per Color/Copywriting tables above.
- `data-testid="stale-rerun-btn"` (existing, e2e-locked). Disabled while submitting (`rerunning`).
- Because D-05 reuses the same `data.stale` field, server-cascade marks appear here identically — trigger line shows the true chain origin (`StaleInfo.triggerAssetId`), no "手动/级联" distinction (CONTEXT-locked).

### 4. Rerun exits (useStaleRerun.ts — LOCKED, zero change)

Two exits, one handler: badge click (§1) + StaleSection button (§3). Guard chain → collect stale chain (self + downstream, `kind==='asset' && stale!=null`) → save-v2 (stale on wire) → orchestrate subset → existing `orchestrate:*` progress UI. **No third exit is added by this phase.**

### 5. Server cascade → client seam (the ONE new interaction wiring — see FLAG-1)

D-01's "客户端零改动复用既有 socket node:updated → triggerStaleCascade 链" is **not literally true today**: `useCanvasSocket.ts` has NO `node:updated` subscription and `canvasApi.ts:648` documents the frontend as not consuming it; `triggerStaleCascade` is currently called only from VariantWall.tsx:206 and NodeDetailPanel.tsx:62.

**Recommended default (Option A — "near-zero" per D-01's own hedge):** add one `socket.on('node:updated', ...)` handler in `useCanvasSocket.ts` (payload aligned to the existing v2/nodes.ts shape `{ node, changedFields? }`). Interaction contract for the handler — strict:
- Merge the node's server truth into the store via the existing transform seam (same pure-function path as `markStaleDownstream`), then call `triggerStaleCascade([triggerAssetId])` for pulse.
- MUST NOT: open/switch the detail panel, change selection, emit toasts, or mutate anything outside the asset node's `stale`-bearing update.
- Idempotent with server truth: server already wrote stale to DB (reload-visible per D-01); local merge + recompute via the same `stale.ts` pure function converges on identical state — divergence impossible by construction.

**Fallback (Option B — strictly zero client change):** server marks are reload-only visible (persisted `data.stale` on wire; REGEN-03-b already proves reload badge survival). Then SC1/SC2 e2e must assert post-reload, and the live pulse is NOT delivered for server-driven cascades. Visual vocabulary identical either way. **Planner decides; Option A recommended** (CONTEXT explicitly leaves "node:updated 的 payload 形状" to discretion, which presupposes a consumer).

### 6. Execute-state truth after D-06③ (engine failure no longer fake-success)

- Engine failure now broadcasts real error → node shows the EXISTING failed badge (right-top「!」, `v3theme.signal.rejected` #DD6A82) and **retains stale** (52-01 red line: `error/failed` never clears `stale` — only `node:state success` clears it, canvasStore L725-730).
- NO new error component, dialog, or copy. Client-side regen failure surface stays the existing 「重生成提交失败: {message}」 toast.
- D-06①②④ (outputs.image reading, /oss/ translation, ref_images/seed passthrough) are data-path only — their visible effect is that the regenerated product's thumbnail/preview actually lands via the existing `node:preview` → thumbnail UI. No styling contract.

### 7. STALE-03 negative contract (visual zero-change invariant)

- Orchestrate/batch execution success MUST NOT cause any `svg[aria-label="stale"]` to appear (or any StaleSection to mount) that was not already present. Architecture-guaranteed (no regen identity on the extra channel → server never marks), asserted negatively in e2e: run orchestrate path → badge count unchanged.
- Locked edges (D-04): isInactive 边不传播、`curation:'locked'` 是传播终点（locked 节点自身永不显示 stale 三角 from cascade — its 🔒 badge vocabulary is untouched）、sequence 边不参与。

### 8. Selector / testid contract (e2e + checker hooks — no new testids)

| Selector | Element | Notes |
|----------|---------|-------|
| `svg[aria-label="stale"]` | stale triangle | canonical visibility assertion (SC1/SC2 positive, SC3 negative) |
| `[data-testid="stale-rerun-btn"]` | StaleSection rerun button | SC4 exit 1 (panel) |
| `svg[aria-label="stale"]` click | badge rerun exit | SC4 exit 2 (badge) — click asserts orchestrate subset body |
| `[data-testid="detail-panel"]` | panel container | for SC4 badge-clears assertion (52-01 success path) |
| `window.__kaisCanvas.getGraph()` | canonical graph bridge | server-cascade graph-state assertions (which nodes carry `stale.triggerAssetId`) |

e2e organization (Claude-discretion area): reuse the phase52-regen/stale-panel mock范式 (save-v2 inject + getGraph + getClaims); pulse NOT asserted (§2).

### 9. Verification mapping

| Req / SC | UI-contract obligation |
|----------|------------------------|
| STALE-01 (SC1) | panel-edit regen success → downstream nodes show `svg[aria-label="stale"]` with no manual action; via §5 seam (live) or reload (fallback); StaleSection shows true trigger origin |
| STALE-02 (SC2) | seed-reroll success → identical assertion surface (same badge, §1) |
| STALE-03 (SC3) | orchestrate/batch success → badge count unchanged (negative assertion, §7) |
| SC4 | stale node rerun via either exit → `node:state success` broadcast clears badge (`toHaveCount(0)`); unrelated nodes unaffected (52-01 chain) |

## Flags for Planner (autonomous-run disclosures)

- **FLAG-1 (wiring, not visual):** the `node:updated → triggerStaleCascade` chain asserted by D-01 does not exist client-side (evidence: `useCanvasSocket.ts` subscription list L136-244 lacks `node:updated`; `canvasApi.ts:648`; `triggerStaleCascade` callers only VariantWall.tsx:206 / NodeDetailPanel.tsx:62). Recommended default: Option A one-handler wiring per §5. Visual contract unaffected either way.
- **FLAG-2 (behavior visibility):** D-06③ converts silent fake-success into visible failure states (failed badge + retained stale + error toast). Existing vocabulary only — locked in §6; no new error surface may be invented by the executor.
- **FLAG-3 (minor):** if planner takes §5 Option A, the handler must subscribe at hook top-level alongside existing `socket.on` registrations and respect the "絶不让它流入 normalizeSocketNodeState" caution at useCanvasSocket.ts:157 (stale-bearing `node:updated` must not be mis-mapped as execution-state — that would violate the 52-01 stale-retention red line).
