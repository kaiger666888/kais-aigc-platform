<objective>
Create the persistence layer for the Skill Contract: add the new `o_skillRegistry` table (REGISTRY-01), add the nullable `skill_id` AND `workflow_phase` columns to `o_assets` (REGISTRY-02 — both columns required per ROADMAP architecture decision #7 and PROJECT.md), add the nullable `skill_id` column to `kv_pipelineRun` (REGISTRY-03), and run a one-time backfill that sets every previously-NULL `skill_id` row to `movie-v1` (REGISTRY-04). The `workflow_phase` column on `o_assets` is added but NOT backfilled — it stays NULL until Phase 31's refactored callbacks populate it (Phase 29 does not own the writer).

Purpose: This is the storage foundation for Phase 30 (default skill seed) and Phase 31 (callback refactor). Without these columns and the backfill, the registry loader in Plan 29-02 has nothing to read and the callbacks in Phase 31 have no `skill_id`/`workflow_phase` to attribute rows to. The `workflow_phase` column closes the prior audit gap on "phase-asset-management" (PROJECT.md line 132: "asset schema 加 skill_id + workflow_phase" — both columns required).

Output: Two existing files modified (src/lib/initDB.ts appends one table; src/lib/fixDB.ts appends three addColumn calls + two UPDATE backfills). No new files.
</objective>
