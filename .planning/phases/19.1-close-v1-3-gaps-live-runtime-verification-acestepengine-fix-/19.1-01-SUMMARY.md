# Phase 19.1 Plan 01: ACEStepEngine Dual-Mode Fix Summary

Dual-mode ACEStepEngine that detects external containers vs localhost and takes the appropriate startup path, fixing the PermissionError crash in Docker deployments where ACESTEP_API_HOST is set to "kais-acestep".

## Changes Made

### Task 1: Add external-host detection to ACEStepEngine.start() (TDD)

**RED commit:** `60084aa` -- test(19.1-01): add failing tests for ACEStepEngine dual-mode detection

**GREEN commit:** `5c04b2e` -- feat(19.1-01): implement ACEStepEngine dual-mode detection (external vs localhost)

**Files modified:**
- `docker/gold-team/src/v6/engines/acestep.py` -- Added `_is_external_host()` helper function with `_LOCAL_HOSTS` frozenset; refactored `start()` to branch on external vs localhost mode at the top
- `docker/gold-team/tests/test_acestep_external.py` -- New test file with 10 tests in 2 classes (`TestIsExternalHost`, `TestACEStepDualMode`)

**Key implementation details:**
- `_is_external_host(host)` returns `True` for any hostname not in `{127.0.0.1, localhost, ::1}`
- In external mode: no subprocess launch, no directory checks, health-check loop with 30s timeout (15 retries x 2s)
- In localhost mode: existing subprocess logic preserved exactly as-is (directory checks, subprocess launch, 120s health-check)
