<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pipeline phase module → write_manifest | Phase code constructs manifest_nodes list; write_manifest is the single gatekeeper that enforces the contract before writing to OSS |
| OSS manifest.json → canvas_sync (Phase 43) | Downstream consumer reads the validated manifest; the contract enforced here is what makes Phase 43's cleanup safe |
| Test fixtures → contract enforcement | Golden fixtures are part of the regression suite; changing MANIFEST_PARAM_SCHEMA or PHASE_REQUIRED_FIELDS causes fixture tests to fail loudly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-01 | Tampering | Phase module constructs node missing required field | mitigate | write_manifest raises ValueError; _validate_node_params checks both baseline + phase-specific requireds |
| T-42-02 | Tampering | Phase emits terse "角色 A" description to bypass content check | mitigate | MIN_DESCRIPTION_LEN = 20; _validate_node_content enforces on stripped length |
| T-42-03 | Repudiation | Bare except swallows manifest write error silently | mitigate | Typed exception handling + AST pre-commit guard (check_manifest_no_bare_except.py) |
| T-42-04 | DoS | Manifest contract test suite slow | accept | 132 tests run in ~0.43s; pre-commit hook tolerable |
| T-42-05 | Info Disclosure | Test fixtures leak internal project data | accept | Fixtures contain synthetic data only (e.g. "角色 小橘", not real PII) |

Security net effect: Phase 42 turns the manifest writer from a fire-and-forget output emitter into a contract-enforcing gatekeeper. Every downstream phase inherits stronger guarantees.
</threat_model>
