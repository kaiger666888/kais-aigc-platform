<objective>
Phase 47 Wave 1 — apply the historical empty-shell backfill. Marked
`autonomous: false` because it mutates production data (the live dev
DB at `data/db2.sqlite`). Requires explicit opt-in by the operator.

The 3-step procedure:
1. **Pre-flight:** confirm `npm run verify:phase-46-contracts` is green
   (the contract gate from Phase 46 Wave 1). If it fails, ABORT — the
   contract is broken and backfilling would paint broken data into a
   contract-violating shape.
2. **Backup + baseline:** copy `data/db2.sqlite` → `data/db2-backup-pre-phase-47.sqlite`.
   Capture the dry-run output to `baseline-snapshot.txt`.
3. **Apply:** `python3 scripts/backfill-asset-descriptions.py --apply`.
   Capture the apply output to `apply-log.txt`. Verify the post-run
   empty-shell count is < 50% of baseline (expect ≥90% reduction
   in practice).

After this plan completes:
- The DB has 417 (or fewer) empty-shell asset nodes repaired with
  synthesized descriptions
- A pre-apply backup exists for rollback
- The contract gate is in place to prevent new empty-shells going
  forward

Plan 47-02 (Wave 2) handles archival + manual sampling.

Output: Mutated DB + backup + snapshot artifacts. No code changes.
</objective>
