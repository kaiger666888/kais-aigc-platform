|----------|-------------|
| Scripts read sibling-repo Python source | Read-only filesystem access; no mutation; paths hard-coded or env-var-overridable |
| Scripts spawn python3 subprocess (VERIFY-01) | Subprocess inherits env; only spawned against the trusted sibling repo path; no shell interpolation of user input |
| Scripts import production TS code (VERIFY-02) | flattenParamsToNodeData is a pure function (no I/O, no network); safe to invoke with fixture data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-01 | Tampering | Attacker sets KAIS_HERMES_SKILLS_PATH to malicious repo | accept | Path is dev/CI-controlled; verify scripts only READ from the path, don't execute code from it (except VERIFY-01 spawns pytest, which is the same trust level as running tests in any repo) |
| T-46-02 | Information Disclosure | pytest output leaks internal data | accept | Test output is dev-only; fixtures are synthetic; no PII |
| T-46-03 | Denial of Service | pytest --no-header -q on 132 tests | accept | Suite runs in <1s; bounded |
| T-46-04 | Tampering | Regex mis-parses Python/TS schema → false positive drift | mitigate | The 9 per-type assertions + summary catch mis-parses as drift; the regex pattern is documented + tested against the known schema shape |
| T-46-SC | Tampering | npm installs | accept | Plan 01 introduces zero new packages — uses pre-existing tsx + node:child_process |

Security net effect: 3 standalone verify scripts with read-only filesystem access and bounded subprocess spawn. No new attack surface.
</threat_model>
