<objective>
Refactor `src/routes/v1/pipeline/submit-to-review.ts` to replace the closed `z.enum(["storyboard", "character", "image", "video", "audio", "compose"])` phase validation with an open `z.string().min(1)` plus runtime registry taxonomy validation. The handler resolves the active skill from the optional `pipelineId` body field (looking up `kv_pipelineRun.skill_id`), defaults to `"movie-v1"` when absent, and distinguishes 400 (phase not declared by skill) from 500 (skill not registered).

Purpose: The old enum silently accepted invalid phase IDs like `image`, `video`, `audio`, `compose` that downstream code couldn't actually handle — they would pass validation then fail mysteriously later. The registry-driven validation surfaces these errors early with a clear message. Per CONTEXT.md decision "submit-to-review Phase Enum Reconciliation": drop z.enum, add handler-side registry check, document the behavior fix (old invalid IDs now correctly fail with 400).

Output: Rewritten submit-to-review.ts with open phase string, skill resolution from pipelineId, and two-tier error handling (400 for unknown phase, 500 for unregistered skill).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external caller → submit-to-review | Untrusted request body. The `phase` field was previously constrained by z.enum; now it's z.string().min(1) with handler-side registry validation. The registry check is the new gate. |
| handler → review platform | The phase string is forwarded to the external review platform via axios. The registry check ensures only declared phases reach the review platform. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-07 | Spoofing | phase field in request body | mitigate | The phase string is validated against the registry taxonomy before any side effect (review platform POST). An unknown phase returns 400. This is STRONGER than the old z.enum which accepted invalid-but-enum-listed IDs. |
| T-31-08 | Information Disclosure | 400/500 error messages reveal skill_id and phase | accept | The error messages include the skill_id (from DB row) and the phase (from request body). Neither is sensitive — skill_id is a public manifest identifier, phase is caller-supplied. The messages are intentionally diagnostic for operator/caller debugging. Internal API, trusted network per v1.6 assumptions. |
| T-31-09 | Denial of Service | DB lookup for pipelineId on every submit-to-review call | accept | The lookup is a single indexed SELECT by primary key (kv_pipelineRun.id). Negligible overhead. If pipelineId is absent (direct curl call), no DB lookup occurs — defaults to movie-v1 in-memory. |
| T-31-10 | Tampering | skill_id resolution from pipelineId | accept | The skill_id comes from the DB row, not the request body. A caller cannot inject a skill_id. The 500 "skill not registered" surfaces any inconsistency. |
</threat_model>
