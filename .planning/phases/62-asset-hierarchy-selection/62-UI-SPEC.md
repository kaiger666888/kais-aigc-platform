# Phase 62 — UI Design Contract（资产管理中心资产层级与选定逻辑）

> Visual and interaction contract for Phase 62. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> 上游契约源：62-CONTEXT.md D-01..D-13（不重议）；本文件只裁 CONTEXT「Claude's Discretion」留下的 UI 自由度。

## Overview

Phase 62 给资产管理中心新增两个 UI 面：

1. **资产层级视图**（HIER-01/02/04）——三层资产组织（域分组 → 候选组 → 候选）+ 层级化选定/批量决策，与既有资产库三态流转并行不悖（零回归）。
2. **pre/final 冗余配置面板**（HIER-03）——khs v2.5 键面快照的读写面，挂载于层级视图内。

本仓无 shadcn / tailwind / 组件库——设计系统是仓内手搓的 `--cv-*` token（`packages/infinite-canvas/src/theme/tokens.css`）+ `am-*` BEM 类（`assetManager.css`）。**本 phase 零新全局设计系统**：全部新 UI 复用既有 token、类与组件（.am-tree / .am-group / .am-card / .am-badge / .am-btn），仅新增少量 `hier-*`/`am-cfg-*` 派生类（复用同一 token 词汇表）。

**既有事实勘误**（planner 必读）：CONTEXT D-01 称「REAL_TYPE_GROUPS 是左侧树既成事实」——实际 `REAL_TYPE_GROUPS`（assetManagerData.ts:269）是**已导出但未被任何组件消费**的数据常量；资产库当前左树是 inferLevel 驱动的「全剧级/场景级/分镜级/管线产出」树（AssetLibrary.tsx:1004-1275）。因此层级视图的域树是**新建 UI**（消费 REAL_TYPE_GROUPS 扩展常量），而非改造既有左树。既有左树保持原样（HIER-04）。

## Information Architecture（层模型）

```
资产管理中心 (AssetManager, viewMode='assets')
├─ 资产库        (assetView='library')     ← 既有，零改动（仅抽 util）
├─ 角色管理      (assetView='character')   ← 既有
├─ 场景管理      (assetView='scene_shot')  ← 既有
├─ 创作文档      (assetView='documents')   ← 既有
└─ 资产层级      (assetView='hierarchy')   ← 新增第 5 个 Tab（本 phase 主面）
   ├─ L1 域导航树（左栏 220px）
   │   ├─ 全部（计数总和）
   │   ├─ 域1 设定资产（角色/场景/道具 + keyframe 扩展）
   │   ├─ 域2 媒体产物
   │   └─ 域3 文本产物
   ├─ L2 候选组折叠卡列表（主区，getGroupKey 组 + 每域末尾「单件资产」桶）
   │   └─ L3 候选卡片网格（复用 renderCard，三态徽标/选定/取消选定/恢复 语义原样）
   └─ 冗余配置右栏（340px，默认收起，toolbar「⚙ 冗余配置」开合）
```

### 层间指派规则（数据契约，e2e 锁死）

| 层 | 指派规则 | 依据 |
|---|---|---|
| L1 域 | **按 DB type** 查 `TYPE_DOMAIN` 常量表（REAL_TYPE_GROUPS 三域扩展）：设定资产 = character/scene/scene_variant/scene_image/prop/prop_key/prop_consumable/costume/accessory/**keyframe**；媒体产物 = video/clip/audio/voice/storyboard；文本产物 = script_phase/outline/topic/storyboard_board/delivery/style/**requirement/story/script**；未列类型兜底 = 媒体产物 | D-01（REAL_TYPE_GROUPS 扩展）。keyframe 归设定域：getGroupKey 的 `keyframe:` 组是 G13 首尾分选核心候选，与角色/场景设定候选同域语义一致。type-first 保证 Notion 文档型资产（requirement/story/script/scene/character 各 doc subtype）按 DB type 自然落域，无需第二套 subtype→域映射 |
| L2 组 | `getGroupKey`（从 AssetLibrary.tsx 提取为共享导出，词表 char:/scene:/keyframe:/type:name 原样）——三态互斥原子单位，**唯一分组轴** | D-02 |
| L2 单件桶 | 每域一个「单件资产」伪组：该域内 getGroupKey 桶 size===1 的资产。**阶段映射静态表标 `reportAudit:true` 的资产不进单件桶显式节点**（不渲染卡片），但其数量计入域级计数聚合 | D-03 |
| L3 候选 | 组内全部资产（三种状态并列展示，非按 tab 拆分） | HIER-01 |

### 计数聚合公式（D-04，逐字复用既有判定式，禁止第二套）

对任意组/域/全局的成员集合 S：

- `selected(S)` = `|{d ∈ S : !!d.isPrimaryView && d.state !== 'eliminated'}|`（AssetLibrary.tsx:503 同式）
- `eliminated(S)` = `|{d ∈ S : d.state === 'eliminated'}|`（:504 同式）
- `pending(S)`（待选）= `|{d ∈ S : !d.isPrimaryView && d.state !== 'eliminated'}|`（:505 同式）
- `total(S)` = `|S|`

DAG 一致性：`candidates = total - selected - eliminated`（model.ts:937 公式）在不变量「淘汰者 isPrimaryView 必为 false」下与 `pending` 恒等；e2e 对同一 fixture 断言层级 DOM `data-count-pending` ≡ DAG 面计数，两侧派生代码都不改（D-04）。

## Component Contracts

### C1 · AssetHierarchy（视图壳，新文件 `AssetHierarchy.tsx`）

- **Purpose**: 第 5 子视图容器；左树 + 主区 + 右栏三段布局；持有域过滤/搜索/批量选择 state。
- **Data-in**: `useRealAssets(projectId)`（与资产库同一模块级缓存 → D-04 同源）；`useCanvasStore` graph（VG 反查用）；共享 util（见下）。
- **States**: loading（复用 .am-loading skeleton）/ error（复用 `资产加载失败：{error}` + 重试）/ 正常态。
- **Interactions**: Tab 切换走既有 `setAssetView` + navPushCallback 快照范式（AssetManager.tsx:37-40 同款）。
- **Integration**: `canvasStore.ts:195` assetView 联合类型加 `'hierarchy'`；`AssetManager.tsx` TABS 加 `{ key: 'hierarchy', label: '资产层级' }`。默认值仍 `'library'`（:1150）——既有 e2e 导航零扰动。
- **Test hooks**: `[data-testid="hierarchy-view"]`（根）；`[data-testid="hier-loading"]` / `[data-testid="hier-error"]`。

### C2 · HierarchyDomainTree（L1 域导航树）

- **Purpose**: 三域 + 全部 的导航/计数聚合/折叠；形态 = 既有左树组件类的直接复用（.am-tree / .am-tree-node--parent / .am-tree-toggle / .am-tree-node__n / .is-on / .is-empty 全套原样，不新造树样式）。
- **Structure**: 顶部「全部」节点（show 全量计数）；其下三个域 section（parent 节点可折叠，默认全展开，复用 collapsedLevels 式 Set state）。域节点**不展开子组**（L2 在主区）——树只有两级深度：域 → （本 phase 无第三级）。这是与资产库左树（域下还有 subtype/实体行）的刻意差异：层级视图的 L2/L3 都在主区卡片化，左树纯导航。
- **Counts**: 域节点徽标 = `★{selected} ○{pending} ✕{eliminated}`（C7 计数芯片规格）；`data-count-selected/pending/eliminated` 属性同值暴露。域计数含 reportAudit 排除项（D-03）。
- **Interactions**: 点击域 → 主区过滤该域（is-on 高亮）；点「全部」→ 清域过滤；折叠箭头独立点击（stopPropagation，与分镜列表折叠交互一致）。搜索框（复用 .am-search，placeholder `搜索资产 / 组…`）按 name/tags/prompt 过滤 L3（过滤命中组保留、组内未命中卡隐藏并计 `data-count-filtered-out`）。
- **Empty**: 域 total=0 → 节点渲染但子态 `is-empty`（灰、计数 0、可点击显示空态主区，不 disabled——域是固定纲不随数据消失，区别于 subtype 空条目的 disabled 处理）。
- **Test hooks**: `[data-testid="hier-domain-node"][data-domain="setting|media|text"]`、`[data-testid="hier-all-node"]`。

### C3 · GroupHierarchyCard（L2 候选组折叠卡）

- **Purpose**: 单个 getGroupKey 组的聚合卡：计数、徽标、批量 checkbox、折叠、内嵌 L3 网格。形态 = 资产库待选 tab 既有 `.am-group` 折叠组卡直接扩展（左侧金竖条互斥组信号保留——`.am-group` border-left: --cv-mod-text-dim 即「互斥组」视觉词汇，沿用）。
- **Header 布局**（复用 .am-group__header 一行排布，新增元素从左到右）:
  1. 组 checkbox（D-06，见 C4）
  2. `.am-group__emoji` + `.am-group__title`（getGroupDisplayInfo 提取共享，title/emoji 原样）
  3. 阶段徽标（见 C6-1）
  4. variantGroup 徽标或「去画布选片 →」（见 C6-2）
  5. 「✋ 手动选择」chip（仅场景/声纹组，见 C4/D-07）
  6. 计数芯片（C7）
  7. 折叠箭头（.am-tree-toggle 复用；折叠只收起 L3 网格，header 常驻 sticky——既有 .am-group__header sticky 行为）
- **States**: expanded（默认）/ collapsed（网格 display:none，header 计数仍全量）；组内含选定者 → title 左侧加 `★` 前缀（与 tab 词汇一致）。
- **Interactions**:
  - 组内单选定：L3 卡片上的「★ 选定」按钮 → 走**提取后的共享 handleSelect**（D-05：既有全语义 + 组映射画布时 fire-and-forget `POST /api/canvas/v2/variant-groups/:groupId/select-winner`，失败仅 toast「画布侧同步失败」不回滚）。提取签名：`selectGroupWinner(assetId, groupKey, ctx)` 放共享 util，资产库路径与本视图同调用点（单组行为逐字节一致 = HIER-04）。
  - 「✕ 取消选定」「↻ 恢复」同 renderCard 既有语义原样。
  - header 双击空白无操作；折叠箭头 stopPropagation。
- **单件桶变体**: title=`单件资产`，emoji=`📦`，左侧金竖条**去除**（非互斥组——加 modifier `.am-group--singleton{border-left-color:var(--cv-line-panel)}`，弱化为普通分组容器）；无 VG 徽标/无 checkbox（单件无批量决策意义，D-06 是组层多选）；卡内 L3 平铺（size=1 时网格单列自然）。桶空则整卡不渲染。
- **Empty**: 组由资产派生，不存在空组。
- **Test hooks**: `[data-testid="hier-group"][data-group-key="{getGroupKey}"]`，计数属性 `data-count-selected/pending/eliminated/total`，折叠态 `data-collapsed="true|false"`；单件桶 `[data-testid="hier-singletons"][data-domain="{域}"]`。

### C4 · BatchActionBar（D-06/D-07 批量决策）

- **Purpose**: 组层多选后的两个批量动作。挂载于层级 toolbar 下方**in-flow 粘条**（非浮层），仅当选中组数 ≥1 时渲染。
- **结构**: `已选 N 组`（mono 计数）｜`批量选定`（.am-btn--primary）｜`批量淘汰`（.am-btn--ghost + 玫红 hover，destructive 位）｜`清除`（.am-btn--ghost）。
- **批量选定语义**（D-06）: 每个选中组各选一个 winner，规则 = 组内**最新非淘汰**候选；场景组/声纹组（isSceneGroup/isVoiceGroup 判定提取共享，AssetLibrary.tsx:557-560 同式）**跳过**且 UI 标注（非静默）；逐组循环走 C3 的共享 selectGroupWinner，不发明组级事务。成功 toast 见 Copy 表。
- **批量淘汰语义**（D-06）: 选中组的全部**待选**候选置 eliminated（有选定的组不动 winner）；场景/声纹组**不豁免**（D-07 只绑批量选定）。
- **Confirmation**: 批量选定**无确认**（与既有单组选定零确认一致，变体可经淘汰态恢复）；批量淘汰**两段式 arm-confirm**——首次点击按钮文案变「确认淘汰 N 组待选？」（玫红实底），再次点击才执行；5s 未二次点击自动解除武装复原。理由：单组流转有光标下即时视觉反馈，批量动作跨组无逐组反馈，加一道防误触（淘汰仍可恢复，非不可逆）。
- **手动组标注**（D-07）: 场景/声纹组 header 恒显 `✋ 手动选择` chip（.am-badge 基底 + --cv-mod-audio 弱底，语义=音频模态既有「声纹徽标」配色词汇 .am-voice-badge）；checkbox **不禁用**（批量淘汰可用），但批量选定跳过时 toast 明示跳过数。
- **Test hooks**: `[data-testid="hier-batch-bar"]`、`[data-testid="hier-batch-select"]`、`[data-testid="hier-batch-eliminate"][data-armed="true|false"]`、`[data-testid="hier-batch-clear"]`、组 checkbox `[data-testid="hier-group-check"][data-group-key]`、手动 chip `[data-testid="hier-manual-chip"]`。

### C7 · 计数芯片（计数聚合展示形态）

### C8 · RedundancyConfigRail（HIER-03 冗余配置右栏）

- **Purpose**: khs v2.5 键面快照（D-10：12 嵌套键 + 3 扁平键）的读侧三源合并展示 + 写侧编辑。挂载 = 层级视图第三栏，toolbar 右侧 `⚙ 冗余配置` 开关（默认**收起**；开时 grid 三列 `220px 1fr 340px`）。
- **Data-in**（读侧）: `GET /api/canvas/v2/generation-config?projectId=&episodesId=` → `{ rows: [{ phaseKey, tier, label, pre, final, source, editable, lockReason? }] }`，服务端完成三源合并（优先级 D-09：覆盖层 > requirement.json 实测 > 快照默认）；`source ∈ override|requirement|snapshot|legacy`（legacy = 旧形态 requirement.json，无 v2.5 键 → 显示快照默认 + 「无 v2.5 键」标注）。
- **行结构**（每 phase_key 一行，.am-diff-row 式横排 + 上下 divider）:
  1. `阶段`：中文显示名（下方 mono phase_key 灰小字）
  2. `档位`徽标：`LLM 产物` / `引擎产物` / `确定性派生` / `文本候选`（.am-badge 基底；确定性派生 = 玫弱底警示，其余中性）
  3. `pre` 数值 + 来源角标（见下）
  4. `final` 数值 + 来源角标
  5. 编辑控件：两个 number stepper（min=1；final 上限 = 当前 pre 输入值，超限即时禁用保存 + 行内错误文案）+ `保存`（.am-btn--ghost；有改动时出现）
  6. 写结果徽标位（保存后出现）
- **确定性派生类 pre 硬上限 1**（D-10）: 5 个确定性派生键（p07_style.style_vector / p07_style.color_intent / p12_compose.master_timeline / p12_compose.audio_mix / p13_master.master_mp4）pre 输入 `disabled`，钉值 1，行内灰字 reason `确定性派生 · pre 固定为 1`；final 开放。后端仍 400 兜底（前端禁用是第一道，非唯一道）。
- **不可配键**（D-11）: 面板底部折叠区 `不可配键 · 30`（默认折叠，summary 可点开）：`p10_voice.tts`（reason `TTS 首选即定（防铺轨污染）· pre 钉死 1`）+ 29 报告/审计类（reason `报告/审计类 · 管线固定`）。行 = 禁用态整行（opacity .45 + not-allowed，同 .am-tree-node.is-empty 词汇），不隐藏。
- **写侧**（D-08 两段式）: 保存 → `PUT /api/canvas/v2/generation-config/overrides/:phaseKey`（body `{ projectId, episodesId, nCandidates, finalCandidates }`）→ 响应 `{ writeState }` → 三态徽标：
  - `已存覆盖层`（青 .am-badge--ok 词汇）
  - `已同步 requirement.json`（青 + ✓ 前缀，最强态）
  - `文件面寻址失败——覆盖层已保存`（玫 .am-badge--warn 词汇；绝不假成功）
- **来源角标**（D-09 可辨）: 数值右下小 chip——`覆盖层`（青弱底）/ `文件值`（金弱底 --cv-mod-text-weak）/ `快照默认`（中性 overlay 底）/ `无 v2.5 键`（中性 + 虚线边，legacy 态）。hover title 显示完整来源说明（Copy 表）。
