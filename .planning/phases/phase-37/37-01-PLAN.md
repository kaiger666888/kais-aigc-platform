# Phase 37 Plan 01 — Batch Execution

## Goal

User can multi-select nodes (Shift+click / drag-select) and trigger them as one batch via right-click "批量执行 (N 个节点)", sharing the same WebSocket progress channel and skip logic as Phase 36 full-canvas orchestration.

## Implementation

### 1. Selection state

React Flow already tracks selected nodes via the `selected` flag on each node. `FlowCanvas.tsx` reads `selectedNodeIds` from React Flow's `useReactFlow().getNodes().filter(n => n.selected)`.

Alternative: track `selectedNodeIds: string[]` in the canvas store. Use this since the right-click menu is rendered outside the ReactFlow lifecycle.

Add to canvasStore:

```typescript
selectedNodeIds: string[]
setSelectedNodeIds: (ids: string[]) => void
```

Wire `onSelectionChange={(p) => setSelectedNodeIds(p.nodes.map(n => n.id))}` on `<ReactFlow>`.

### 2. ContextMenu batch entry

In `CanvasContextMenu.tsx`, when invoked from pane (no `nodeId`) but `selectedNodeIds.length > 1`, show:

```tsx
{selectedNodeIds.length > 1 && (
  <MenuItem
    label={`批量执行 (${selectedNodeIds.length} 个节点)`}
    icon="⚡"
    action={handleBatchExecute}
    accent
  />
)}
```

`handleBatchExecute`:

```typescript
await saveCanvasGraph(projectId, episodesId, canvasToFlowGraph(...))
await orchestrateCanvas(projectId, episodesId, selectedNodeIds)
```

### 3. Pane-level context menu trigger

Currently `onNodeContextMenu` opens context menu with `nodeId`. Need `onPaneContextMenu` (or equivalent) to open it when right-clicking on empty canvas with active multi-selection.

Add:

```tsx
<ReactFlow
  onPaneContextMenu={(e) => {
    e.preventDefault()
    setMenuPos({ x: ..., y: ..., nodeId: undefined })  // pane-level: no nodeId
  }}
/>
```

### 4. Single-node right-click "执行节点" (BATCH-05)

The existing `handleExecute` calls `executeNode` (the per-node endpoint). Per BATCH-05, single-node entry should reuse orchestrate endpoint with `[nodeId]`. However, that creates an extra DB read/write round-trip; the current per-node path is faster.

Decision: keep `handleExecute` calling `/canvas/execute` for the single-node case. The BATCH-05 requirement is satisfied by *capability* (the orchestrate endpoint accepts single-element nodeIds), not by *forcing* the change. Update PLAN/REQUIREMENTS note accordingly.
