# Quick Task 260703-iw6: 独立骨骼动作引导视频工作流 + MSR可选消费

## Goal

新增独立 pose-video 工作流 (Kimodo BVH → Blender → LTX I2V)，并让 MSR 可选消费其骨骼渲染帧。两者解耦：poseVideo 独立产出动作视频，MSR 只在收到 poseVideoFrames 时才注入。

## Context (locked)

- Spec: `/tmp/gsd-task-ltx-pose-pipeline.md`
- Kimodo TaskCreate schema requires `task_id` + `type` + `params` (caller assigns task_id; payload fields go under params)
- Blender `/render/bvh` requires `bvh_path` (host path under /mnt/agents/output) — returns rendered PNG paths
- LTX I2V workflow uses: CheckpointLoaderSimple(ltx-2.3-22b-distilled-1.1) + LTXAVTextEncoderLoader(gemma_3_12B_it_fp8_scaled) + LTXVImgToVideoConditionOnly(strength=0.7) — validated, NOT the MSR workflow
- buildMSRWorkflow in msr.ts already supports dynamic ref count via filenames array — no signature change needed

### Task 1: Add poseVideo route (NEW FILE)

**Files:**
- `src/routes/production/ltx/poseVideo.ts` (NEW, ~300 lines)

**Action:**
1. Standard scaffolding (express Router, multer for ref1, zod validation, copyToContainer helper copied from msr.ts pattern)
2. Config additions: `LTX_CONFIG.kimodoUrl` (`http://localhost:8002`), `LTX_CONFIG.blenderUrl` (`http://localhost:8095`), `LTX_POSE.defaultPoseFrameCount`, etc. — read from existing config; only add the two URLs to LTX_CONFIG
3. `pollKimodoTask(taskId)` — poll `GET /api/v1/tasks/{id}` every 2s until status ∈ {completed, failed}; timeout 10min
4. `submitKimodoMotion(prompt, duration)` — POST `/api/v1/tasks` with body:
   ```json
   {
     "task_id": "<uuid>",
     "type": "motion_generate",
     "params": {
       "prompt": "<motionPrompt>",
       "duration_sec": <duration>,
       "output_format": "bvh",
       "model": "kimodo-smplx-rp"
     }
   }
   ```
5. `renderBvhInBlender(bvhPath, cameraAngles, resolution, framesPerAngle)` — POST `http://localhost:8095/render/bvh`; return rendered PNG absolute paths
6. `buildPoseVideoWorkflow(opts)` — LTX I2V workflow per spec (16 nodes; class_type IDs match the validated I2V workflow, NOT MSR)
7. Route handler:
   - Validate projectId + prompt + ref1 file
   - Submit Kimodo → poll → extract BVH path from `outputs` (try outputs.bvh, outputs.video, then scan OUTPUT_DIR for newest .bvh)
   - Call Blender → extract first front PNG
   - docker cp PNG into comfyui input dir
   - Build + submit LTX I2V workflow
   - Return: `{ promptId, status: "pending", poseVideoId: <uuid>, stages: { bvh, blender, ltx } }`
   - Cleanup local multer files
   - Errors: 502 for upstream failures, 400 for validation, 504 if Kimodo timeout
