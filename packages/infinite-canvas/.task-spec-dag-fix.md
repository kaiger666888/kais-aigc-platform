## 问题1：时间轴折叠按钮位置

### 现状
「收起播放器」按钮目前在统计栏右侧（与提示文字并排）。

### 要求
按钮应移到**左边播放器区域的边缘**（靠近播放器），不是在统计栏里。

具体方案：
- 在播放器列和分镜列表之间放一个**竖向窄条**（宽 24px），内含折叠/展开按钮
- 展开态：窄条显示 `◀` 箭头（点击收起），鼠标悬停高亮
- 折叠态：窄条显示 `▶` 箭头（点击展开），窄条仍在原位（左边边缘）
- 移除统计栏中的「收起播放器/展开播放器」按钮
- 统计栏提示文字保留（展开=「单击播放视频」，折叠=「单击选中分镜」）

布局示意（展开态）：
```

[播放器 360px][◀ 24px][分镜列表 flex:1    ][竖幅时间轴]
```

折叠态：

## 问题2：管线 DAG 全面修正

调查发现的错误清单：

### 2.1 换装Turnaround 显示"运行中"
**根因**：DB 中 11 个 costume turnaround 节点，只有 2 个 state='success'，8 个 state 为空（未生成），1 个 eliminated。`deriveDagState` 规则：`total > 0 && completed < total → running`。
**修复**：不需要改逻辑——状态显示是正确的。但需要确认 `costume-turnarounds` 的 match 规则能正确匹配到 costume 节点。

检查 DB 实际数据：
```sql
SELECT id, json_extract(data, '$.turnaroundType') as trType, json_extract(data, '$.state') as state 
FROM canvas_nodes WHERE projectId=1785508691757 AND id LIKE 'a-turnaround%';
```
- gray_base: 8 个全 success
- costume: 2 success + 8 state为空 + 1 eliminated

**问题**：state 为空的节点是否被 `isDoneState` 正确处理？当前 `isDoneState` 只认 'success'/'cached'，空 state → 不是 done → 计入 running。这是**正确的**行为——costume turnaround 确实只有 2/11 完成，正在运行中是合理的。

**不需要修改此节点逻辑**。

### 2.2 换装TR 应该作为首尾帧输入（而非灰底TR）

**调查结论**：实际 KMC 管线中，P11 用的是**灰底 base_turnaround**，不是换装 costume turnaround。这是正确的（H3 ref2va 使用灰底 TR + 场景图做参考）。

但用户的设计意图是：**换装TR 应该替代灰底TR 作为 P11 的输入**（因为换装包含服化道信息，更真实）。

**DAG 应该反映用户的设计意图**，不是当前代码的实现现状。所以：
- 修改边：`turnaround-sheets → first-last-frames` 改为 `costume-turnarounds → first-last-frames`
- 或者：两条边都保留（灰底TR和换装TR都是首尾帧的输入参考）
- 建议：保留 `turnaround-sheets → first-last-frames`（灰底是基础参考），**新增** `costume-turnarounds → first-last-frames`（换装是进阶参考）

### 2.3 首尾帧不只有一种选项——需要拆分条件模式

**现状**：DAG 中只有一个 `first-last-frames` 节点。

**KMC 实际模式**（P11 video render 的多种条件输入）：
1. **纯 Prompt**：无参考图，仅文字描述 → 生成首帧/尾帧
2. **只有首帧**：仅首帧条件
3. **只有尾帧**：仅尾帧条件
4. **首尾帧**：首帧+尾帧条件
5. **多参考**：多张参考图（角色+场景组合）

**修改方案**：将 `first-last-frames` 拆分或添加子节点：

在 DAG_NODES 中新增/修改：
```typescript
// ── P11 视频渲染（post） ──
{ id: 'iframe-generation', label: '条件帧生成', phaseCode: 'P11', phaseIndex: 11, group: 'post',
  match: { phaseIndex: 11, idIncludes: 'first_last_frames' }, expectedCount: 'dynamic' },
{ id: 'video-clips', label: '视频片段', phaseCode: 'P11', phaseIndex: 11, group: 'post',
  match: { phaseIndex: 11, stage: 'video' }, expectedCount: 'dynamic' },
```

将原来的 `first-last-frames` 改名为 `iframe-generation`（条件帧生成），保持 match 规则不变。

**更重要的是修正依赖边**，让状态机反映正确的依赖关系。

### 2.5 DAG 节点状态聚合修正——检查 phase 级错误

**问题**：P11 phase 实际 error（GLM 429），但 video-clips 节点显示 completed（因为 5 个历史 LTX 扫描节点全 success）。

**修复**：在 `deriveDagModels` 中增加 phase 级错误检测：

在 `deriveDagState` 函数中，如果同 phaseIndex 存在 `n-*` script 节点 state='error'/'failed'，且该 DAG 节点 total < expected（或 total 过少），则降级为 `failed` 或 `running`。

实现方案（在 model.ts 中）：

1. 新增参数 `phaseErrors: Set<number>`（有 error script 节点的 phaseIndex 集合）
2. 在 `deriveDagModels` 中，先扫描所有 `n-*` 节点的 state，构建 phaseErrors
3. 传入 `deriveDagState`，当 `phaseErrors.has(phaseIndex) && completed < expected` 时返回 'failed'
