## 问题 1: 详情 drawer 图像下部分被遮住
**文件:** `assetManager.css`

当前 drawer 布局:
```css
.am-drawer{position:absolute;top:0;right:0;bottom:0;width:620px;...display:flex;flex-direction:column;overflow:hidden}
```

drawer 内是 AssetDetail 组件，它的 `.am-det` 是 `grid-template-columns:1.1fr 1fr;height:100%`。

左侧 `.am-det__stage` 是 `flex:1;overflow-y:auto`，图片 `.am-det__big-img` 是 `max-width:85%;max-height:100%`。

**问题：** 竖图（9:16）在 drawer 里高度受限，`max-height:100%` 让图片高度 = stage 高度但宽度按比例可能超出，或者 `.am-det__views`（底部视角切换栏）占了空间导致 stage 高度不够。

**修复方案：** 
- `.am-det__big-img` 改为 `max-width:90%;max-height:calc(100% - 10px);object-fit:contain;border-radius:8px`
- 确保 `.am-det__left` 是 `display:flex;flex-direction:column;min-height:0`（已有）
- `.am-det__stage` 确保 `min-height:0`（flex item 默认 min-height:auto 会撑开）

在 CSS 文件中找到 `.am-det__stage` 规则并添加 `min-height:0`。
找到 `.am-det__big-img` 规则并确认 `max-height:100%` 足够（如果 stage 有 padding 可能不够）。

## 问题 3: 有些人物有相关版本的进入了选定资产（分组错误）
**文件:** `AssetLibrary.tsx`

当前 `getGroupKey` 函数：
```tsx
function getGroupKey(d: AssetDetail): string {
  if (d.characterId) return `${d.type}:${d.characterId}`
  return `${d.type}:${d.name}`
}
```

**问题分析：** 当 `characterId` 为空时，回退到 `type:name`。如果同一角色有不同变体但 name 不完全一样（比如 "沈知意-v1" 和 "沈知意-v2"），它们会被分到不同组。或者不同 type 的资产（比如 `turnaround_sheet` 和 `scene_image`）因为 type 不同也被分到不同组，导致每组各有一个 primary，所以一个角色有多张图进入选定资产。

**真正的问题：** 用户注册的资产可能有不同的 `type` 值（如 `character_design` vs `turnaround_sheet` vs `scene_image`），导致同一个角色被分成多组。每组 auto-init 时各选一个 primary。

**修复方案：** 
修改 `getGroupKey`，对于角色类资产（type 包含 character/turnaround），统一用 characterId 分组，不拼接 type：
```tsx
function getGroupKey(d: AssetDetail): string {
  if (d.characterId) {
    // 角色类资产按 characterId 统一分组，不区分 type
    // 这样同一角色的 turnaround_sheet / character_design / 3d_model 都在同一组
    return `char:${d.characterId}`
  }
  // 场景类资产按 characterId（实际存的是场景ID如 S01）分组
  if (d.type === 'scene' || d.type === 'scene_variant' || d.type === 'scene_image') {
    return d.characterId ? `scene:${d.characterId}` : `scene:${d.name}`
  }
  return `${d.type}:${d.name}`
}
```

同时，auto-init 逻辑也需要同步修改：确保每个组内只选一个 primary。修改 auto-init 中的分组判断，使用新的 `getGroupKey`。
