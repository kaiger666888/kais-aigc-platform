## 当前审计结果

运行 `python3 scripts/audit-api-contract.py` 发现 2 个不匹配：

### 问题 1: ReviewCard.tsx 调用不存在的后端路由

文件：`packages/infinite-canvas/src/components/ReviewCard.tsx`
- 第 57 行：`fetch(`${apiBase}/api/v2/canvas/review/options`)` → 后端不存在 `/api/v2/canvas/review/`
- 第 78 行：`fetch(`${apiBase}/api/v2/canvas/review/submit`)` → 后端不存在 `/api/v2/canvas/review/`

后端实际存在的 review 路由：
- `/api/canvas/review/approve` (POST)
- `/api/canvas/review/reject` (POST)
- `/api/canvas/review/score` (POST)
- `/api/canvas/v2/review-gate` (POST)

### 修复方案

ReviewCard.tsx 的 options/submit 功能是一个未完成的前端组件预留。这两个 API 调用：
- `options` — 加载审核选项（多个创意方案供选择）
- `submit` — 提交选中的方案

由于后端从未实现这两个端点，且 ReviewCard 是独立组件（不影响资产管理中心核心功能），修复策略：

**方案 A（推荐）：给 ReviewCard 的 fetch 调用加 graceful 404 容错**
- 在 `.catch()` 中已经做了空处理（`.catch(() => {})`），所以 404 不会崩溃
- 但应该加一个 `console.warn` 提示开发者这个端点还未实现
- 在组件加载时如果 404，显示"审核选项暂不可用"而不是静默失败

**不要删除 ReviewCard 组件**——它是已设计但待实现的 feature。

## 需修改的文件

### 1. ReviewCard.tsx — 加 404 容错 + console.warn

修改 `packages/infinite-canvas/src/components/ReviewCard.tsx`：

在两个 `fetch` 调用的 `.then()` 中，检查 `json.code === 404` 的情况：
```typescript
.then(json => {
  if (json.code === 404) {
    console.warn('[ReviewCard] Review options API not implemented yet')
    return
  }
  if (json.code === 200 && json.data?.options) {
    setOptions(json.data.options)
  }
})
```

对 submit 的 fetch 也做同样处理。

在 loading 完成后 options 为空时，显示"审核选项暂不可用"而不是空白。

### 4. 审计脚本增加动态路由匹配改进

当前 `path_matches()` 函数只处理了 `:skillId` 和 `:taskId` 和 `:projectId`。
需要泛化为处理所有 `:param` 形式的动态路由。

修改 `path_matches` 函数中的正则替换：
```python
# 通用化：所有 :xxx 参数都替换为 [^/]+
bp_pattern = re.escape(bp_clean)
bp_pattern = re.sub(r"\\:([a-zA-Z_]+)", r"[^/]+", bp_pattern)
```
