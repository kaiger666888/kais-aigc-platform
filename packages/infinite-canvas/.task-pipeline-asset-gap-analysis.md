### 5.3 缺失的 4 个中间步骤总结

**步骤 ④⑤⑥⑦ 完全缺失于资产管理中心 UI**，这 4 个步骤正是连接「设定图」到「首尾帧」之间的关键中间产物链：

```
character_concept ─→ turnaround_base ─→ [costume_turnaround ⑦ ❌] ─┐
                                                                     ├──→ keyframe_first ⑧
scene_concept ─→ [scene_multiview ④ ❌] ─→ [scene_angle_shot ⑥ ❌] ─┤
                                              ↑                      │
                              [storyboard_design ⑤ ❌] ──────────────┤
                                                                     └──→ keyframe_last ⑨
```

缺失的不仅是资产展示，更是**生成链的溯源关系**。当前 UI 无法回答"这个首帧是基于哪个场景角度图和哪个定妆 turnaround 生成的"，因为：
1. 中间产物 ④⑤⑥⑦ 不在数据库
2. o_assets 无 provenance / input_refs 字段记录依赖
3. canvas_links 有 348 条边但资产管理中心不消费

### 5.4 其他 UI 数据层问题

1. **CharacterWardrobe 期望视角拆分但 DB 无数据**：组件设计了 face_cu/front/side/back 四宫格布局（`TURNAROUND_LAYOUT`），但 DB 中所有 character 资产 viewAngle 全空，四宫格无法填充。
2. **AssetLibrary 层级树推断不精确**：`inferSubtype()` 通过正则猜测 turnaround_sheet/turnaround_view/character_concept，但因 o_assets 无 subtype 字段，推断可能不准。
3. **o_assets.workflow_phase 全空**：无法按管线阶段筛选资产。
4. **AssetDetail 组合关系图为 mock**：使用 `COMPOSITIONS` 常量（小橘/小月的 mock 数据），与真实项目无关。

## 六、重构建议

### 6.1 数据层：将中间产物注册到 o_assets

**核心问题**：canvas_sync 只将 P04（character）、P07 部分（scene_images）、P11（keyframe）同步到了 o_assets，而 P07 的三视角、P09 的 storyboard、P11 前置的 scene_angle_shot 和 costume_turnaround 未同步。

建议方案：

| 优先级 | 动作 | 说明 |
|--------|------|------|
| P0 | **扩展 canvas_sync 同步范围** | 将 p07_scene_generation 的 angle 节点（④）、p09_shot_breakdown 的 storyboard 节点（⑤）注册到 o_assets |
| P0 | **新增 scene_angle_shot 资产类型** | 将 p09 storyboard 节点的 scene_ref 指向的场景角度图抽取为独立 o_assets 记录（type=scene_angle_shot 或复用 scene + viewAngle） |
| P1 | **扫描注册 costume_turnaround** | 将磁盘 `turnaround_final/` 下的文件注册到 o_assets（type=character, viewAngle=final 或新增 type=costume_turnaround） |
| P1 | **填充 workflow_phase 字段** | 同步时写入 p04/p07/p09/p11 等阶段标识 |
| P2 | **添加 provenance 关系** | 实现 SKILL.md V2.1 设计的 Asset Provenance Chain，记录 input_refs → output 依赖链 |

### 6.2 UI 层：扩展资产管理中心覆盖全链路

**方案 A（推荐）：按生成链重新组织 Tab**

将当前 3 Tab 扩展为按生成阶段分区的 **5 Tab**：

| 新 Tab | 展示内容 | 数据来源 |
|--------|---------|---------|
| 资产库（保留） | 全部资产的平铺网格 + 层级树 | o_assets 全量 |
| 角色设计（重构） | ①角色设定图 → ②灰底 turnaround → ⑦定妆 turnaround 的三级链 | o_assets character (concept/base/final) |
| 场景设计（重构） | ③场景设定图 → ④三视角多视图 的两级链 | o_assets scene + angle 节点 |
| 分镜设计（新增） | ⑤E-Konte 分镜列表 + ⑥每镜场景角度图 | o_assets storyboard + scene_angle_shot |
| 首尾帧（保留/拆分） | ⑧首帧 + ⑨尾帧流水线 + 连续性 | o_assets keyframe |

**方案 B（渐进）：在现有 Tab 内增加中间产物区段**

在 CharacterWardrobe 增加"定妆 Turnaround"区段（⑦），在 SceneShotManager 层1和层2之间增加"分镜设计"区段（⑤）和"场景角度图"区段（⑥）。

### 6.3 追溯关系：资产溯源链可视化

当前 SKILL.md V2.1 已设计了 Asset Provenance Chain（每节点记录 input→tool→output + 依赖边），canvas_links 表已有 348 条边。建议：

1. **资产管理中心增加"溯源视图"**：点击任一资产，展示其上游输入和下游产出（DAG 子图）
2. **o_assets 增加 `input_refs` 字段**：JSON 数组，记录依赖的 asset uuid 列表
3. **AssetDetail 的组合关系图从 mock 切换为真实 provenance 数据**

### 6.4 实施路径建议

```
Phase 1（数据补全）：扩展 canvas_sync → 注册 ④⑤⑥⑦ 到 o_assets
                     ↓
Phase 2（UI 适配）：  AssetLibrary 层级树增加 scene_multiview/storyboard 类型
                     CharacterWardrobe 修复 viewAngle 空值问题
                     ↓
Phase 3（溯源链路）：  o_assets 加 input_refs 字段 + AssetDetail 切换真实关系图
                     ↓
Phase 4（Tab 重构）：  按方案 A 拆分 5 Tab，完整覆盖 9 步生成链
```
